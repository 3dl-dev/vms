# Written reasons for tier-1 programs that are not run-pass in either scoreboard
# column (vms-44a, roadmap R2). Rendered into docs/corpus-scoreboard.md; the gate
# tests/integration/test_corpus_scoreboard.sh fails when a program that is neither
# run-pass nor compile/link-failing (those carry the harness's own error text) has no
# line here -- a failing program must say why.
#
# format:  <program>  <class>  <reason ...>
#
# classes:
#   ptr32       a source idiom that assumes 32-bit pointers; cannot hold in a 64-bit image
#   executive   needs an OVMX executive facility that does not exist yet (tracked item)
#   product-gap an OVMX service the program exercises is wrong/absent (tracked item)
#   flaky       passes in some environments and not others; held out of the floor until fixed (tracked item)
lib_callg   ptr32       LIB$CALLG takes an argument list of 32-bit longwords holding pointers; the program asserts sizeof(unsigned)==sizeof(void*) (vms-95b)
lib_que     ptr32       interlocked queue entries are linked by 32-bit self-relative displacements; the program's entries and header sit in a 64-bit address space (vms-95b)
sys_forcex  flaky       timing-dependent: a spawned DCL subprocess plus two 5s sleeps; passes on a local KVM guest, hangs to the 40s budget on the CI runner; held at its CI verdict until the race is root-caused (vms-f45)
