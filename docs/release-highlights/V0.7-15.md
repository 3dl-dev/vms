## Highlights

- **Remote files over DECnet (vms-6a4).** OVMX's own DCL runs `DIRECTORY node::spec` and `TYPE node::spec` through the remote FAL (#1962). A live round trip against a real VAX runs OVMX's `DIRECTORY`, `TYPE` and `COPY` of `node::spec` against the VAX, and the VAX's `COPY` and `DIRECTORY` against OVMX (#1966). RMS itself does remote file access over DAP, so DCL's `DIRECTORY`, `TYPE` and `COPY` of `node::spec` are plain RMS clients. A 2,000-record and a 20,000-record `COPY` go both ways against the real VAX with equal checksums, now that NETACP honours NSP flow control, retransmission and NAKs (vms-0a7, vms-985, #1994). A restarted OVMX does not reopen a peer's still-held NSP link address (#1958), and its first `SET HOST` to a real VAX after a reboot is accepted (#1964). OVMX runs one NETACP per node, and NETACP no longer keeps its whole idle session pool resident (#1940). A network object's server process reports NETWORK from `F$MODE`, `JPI$_MODE` and `JPI$_JOBTYPE` (#1938). The booted NETACP (`DECNETD.EXE`) finds its LAN unit and waits through VMS services, not the host C library, and its datalink is executive-resident (#1355, #1977). #1977 removed the `getifaddrs` interface lookup and the terminal `poll`. What remains in `DECNETD.EXE` is the FAL and COPY server threads (`pthread_create`) and the FAL-pump `poll`, which sit in argv-flag self-test paths that the booted NETACP does not reach. Removing them is open (vms-0a7, vms-d3cd).
- **Cluster lock manager failover (vms-874f, vms-427, vms-2fa, vms-0db, vms-326).** A survivor re-sends the locks it holds in a departed master's tree as op-0x08 rebuild records. As the new master it installs the records another survivor sends (#1936). A holder told 0xf9 installs its own lock's value block on the resource it now masters, and the deferred grant carries that value block (#1952). Lab captures pin down when a survivor's op-0x08 records follow the barrier (release 5 if its LOCKDIRWT is non-zero, 6 if zero) (#1943), and show a real holder sending its waiting and converting locks (#1956). The executive takes RMS's file-access lock under the name and identity a real VAX uses (#1937). `sys$getlki` `LKI$_RESNAM` returns the resource name's own byte count, NULs included (#1945), and `SYS$GETLKIW` answers `LKI$_PID` from the lock block (#1981). A survivor's queued `$ENQ` rides out a quorum hang when its master departs (#1975), and `ci6_evac.sh` drives and grades the ci.6 evacuation gate (#1974).
- **A cluster state transition no longer crashes a real VAX (vms-8cb5).** A transition discards all lock-directory information, so OVMX now discards its own record of which entries it registered with each directory node. Before this fix, OVMX could send a removal for an entry that the VAX had already dropped in the rebuild, and the VAX stopped with a `LOCKMGRERR` bugcheck. The browser cluster demo's visitor gate caught this. It had been latent since V0.7-12, so V0.7-12 through V0.7-14 could crash the demo's VAX in some join orders (#2015). The XQP's `F11B$` volume locks are system-wide kernel-mode resources, so OVMX's volume lock reaches the VAX that holds it (#1989). A file header change on OVMX reaches a VAX's cached copy through the XQP's per-file `F11B$s` lock and its value block (#2003). A real VAX's lock-directory lookup sent during a transition is answered, including when the new vector names a third member (#2023, #2029). An OVMX master re-registers its directory entries after the rebuild (#2017), and a sub-resource is never looked up in the node's own directory (#2033). On the merged code, the three-node browser demo bed (two OVMX nodes and a real VAX) formed the cluster in 80 of 80 runs across two join orders, with no hangs and no bugchecks (vms-8cb5).
- **GCC's cc1 builds on OVMX/Alpha (vms-465, vms-d2a).** `BUILD_CC1.COM` builds GCC's `cc1` on OVMX/Alpha, across 8 CI shards. The RMS, LIBRARY, LINK and DCL fixes the build needed land with it (#1907). The C RTL places P0 mappings lowest-first, so a fragmented P0 still has room for a large request (#1939). `<inttypes.h>` uses `ll` for `PRId64` and its relatives, as the LLP64 alpha-dec-vms C RTL does (#1941). The Alpha executive module `vms.ko` now ships in the co-release bundle and is byte-reproducible under `SOURCE_DATE_EPOCH` (#1960). A compiler's `exit(1)` on OVMX/Alpha is a failure status (#1973). Every release cut ships a bootable OVMX/Alpha set (`vmlinux-boot` and `ovmx-distrib-alpha.img`). The release-acceptance gate boots it from the cut bundle to DCL, and a negative control turns the gate red on a wrong version (vms-f10, #1972). A FAB's `fab$l_xab` is `void *`, as in DEC C, so it chains any XAB type (#1984).
- **DECC$SHR's heap, clock and signals go through VMS services (vms-bc53, vms-593, vms-931).** `malloc` takes its address space from `SYS$EXPREG`/`SYS$DELTVA`, which the executive serves and charges to PGFLQUOTA. The C RTL makes no Linux `brk`, `mmap` or `munmap` call on the heap (#1982). The clock is `SYS$GETUTC`, and the time zone comes from the `SYS$TIMEZONE_*` logicals, so a `DEFINE` of the differential moves the next `localtime()` (#1979). Signals are VMS conditions: `raise()` is `LIB$SIGNAL`, `alarm()` is `$SETIMR` with an AST, `pause()` is `$HIBER`, and `kill()` of a VMS PID is `$FORCEX`, `$DELPRC` or `$SUSPND`/`$RESUME`, authorized by the executive (#2005). Process creation is `$CREPRC`: `exec*`, `wait` and `getpid` go through the executive, and a creator and its new process meet in the executive's creation record, not a host pipe (#1985, #2022, #2030). Terminal I/O is `$QIO` on `SYS$OUTPUT`, `pipe()` is a mailbox pair, and no C RTL file name reaches the Linux VFS (#1997). Sockets are `$QIO` on `BGn:` channels, and TCP/IP `SHOW INTERFACE` reads the executive (#1980). The Alpha DECC$SHR links this code, and an activated x86_64 or aarch64 DECC$SHR program gets the same VMS terminals, pipes, names, clock and signals (#2031).
- **A smaller kernel that boots more hardware (vms-fee, vms-c5f).** The x86_64 kernel image is 34% smaller (13.6 MB to 9.0 MB, zstd). Drivers for real hardware (NVMe, Intel NICs, SCSI HBAs, MMC, USB serial and more) ship as 134 signed zstd modules. A size-budget and hardware-coverage gate keeps both in place (#1968). `LINK.EXE` takes the VMS `LINK` command through `CLI$DCL_PARSE`, with `/MAP`, `/INCLUDE` and options files, and the shipped image carries no build flags (#1995).
- **DCL matches VAX V7.3 byte for byte.** These features are byte-checked against VAX V7.3: `ON`, `SET NOON` and `EXIT` (#1942); `GOTO`, `GOSUB`/`RETURN`, block `IF` and `CALL` (#1953); and symbol typing, where a symbol keeps its own type and `$STATUS` is a string (#1951). `SHOW TIME` prints no hundredths and leaves `$STATUS` %X00030001, as VAX V7.3 and Alpha V8.4 do (#1954). `$MOUNT` refuses a second volume with the label of a mounted one (`%MOUNT-F-VOLALRMNT`) (#1893). DCL file verbs take a P1 list of any length, checked against a real VAX V7.3 (#1970). `OPEN`, `READ`, `WRITE` and `CLOSE` are byte-checked against VAX V7.3, and DCL runs a procedure and reads and writes `SYS$INPUT` and `SYS$OUTPUT` through RMS and `$QIO`, with no host path (#1965). Executive records written after startup reach OPERATOR.LOG on Linux, without a placeholder OPCOM (#1845). The system time is the executive's: `$GETTIM` and `$GETUTC` read one cell, and `$SETIME` and `SET TIME` change it (#2007).

## Known open items

- **`$PROCESS_SCAN` given an unreadable criterion address hangs the caller** instead of returning `SS$_ACCVIO` (vms-705).
- **On OVMX/Alpha the guest's time stamps carry the year 2006** (vms-aedb).
- Remastering is not proven in a cluster evacuation yet (vms-ci.6).
- **DCL still reaches the host C library in many places.** Its output and messages still have a stdio path beside `$PUTMSG`, RMS and `$QIO` (vms-c53, vms-d4a0). Command modules such as `dcl_cmd_misc.c`, `dcl_cmd_file.c` and `dcl_cmd_process.c` still do file I/O through it (vms-0504, vms-2cbe, vms-ed75). Image activation on the fork path uses a host pipe and `poll()` (vms-89bb, vms-6d9). The audit continues under the `libc-drop` label.
- **`DECNETD.EXE` still parses Unix-style `--flags`** instead of taking its parameters the VMS way (vms-18c9).
- **The BG socket veneer waits with `poll()`** (vms-c541).
