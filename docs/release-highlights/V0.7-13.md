## Highlights

- **OVMX/VAX Node B no longer runs out of memory during startup (vms-4029, vms-83d).** Node B is a small VAX, and it had been losing its memory before STARTUP.COM finished. It now stages the heavy `SYS$SYSTEM` utilities on first use instead of all at boot (#1784), and DCL symbols take the space of their value instead of 4.4 KB each (#1793). A new 16 MB VAX CI leg with a free-memory floor guards this (#1794), and the public demo boots Node B with 32 MB, a MicroVAX 3900 configuration (openvmx-site #82). The pre-tag visitor gate on the release candidate (openvmx-site run 39187392378, Node B built from the candidate at 32 MB) passed 8 of 8 join orders with 0 VAX bugchecks, and the same gate on the tagged commit (run 39197016741, Node B built from it) passed 8 of 8 again; the real VAX admitted both OVMX nodes, offered Username:, and both OVMX nodes reached a logged-in DCL prompt in every order. One run per order is evidence, not proof.
- **The visitor gate no longer mistakes a late login for a failure (vms-25f).** The gate was racing a login prompt that arrives late; it now starts the login over like a visitor would, with a bounded and counted retry (#1804). This changes how the demo is proven, not what OVMX does.
- **Shell and toolchain work toward self-hosting.** DCL `LINK` runs LINK.EXE with VMS syntax and an options file (vms-ce4, #1791). On OVMX/Alpha, the real `xgcc` driver runs `cc1` and `as` (vms-1eb, #1789), GNU `as` assembles `cc1`'s output (vms-5303e, #1746), and cc1, as and LINK.EXE built for the alpha-dec-vms host compile, assemble and link a C program (vms-e40, #1790). `$LKWSET` and `$ULWSET` lock and unlock pages (vms-18c2, #1779).
- **DCL commands reject qualifiers they do not implement (vms-097).** `READ`, `WRITE`, `LIBRARY`, `TELNET`, `FTP`, `MAIL`, `RUN`, `SET` and `SHOW` answer `%DCL-W-IVQUAL` for an unsupported qualifier, `READ` honours `/END_OF_FILE` and `/ERROR=label`, and `WRITE` honours `/SYMBOL` and `/ERROR=label` (#1782, #1796, #1801, #1795, #1797, #1783, #1798, #1799). Eleven stale "absent" rows in the compatibility register were re-grounded against the source (#1802).
- **Faster, tiered CI.** Heavy legs run nightly and before a tag, and are path-filtered in the merge queue (#1749). This changes how a release is proven, not what it does.

## Known open items

- **A rare console-input wedge remains (vms-25f residual).** In about 1 of 50 throttled runs during development, a cluster node's console stopped taking input after a login timeout and the visitor could not log in. No peer crashes. It is not fixed in this release.
- **The 0b/05 database request names transfer connection 0**, where real requests name one (19 of 19 in the capture corpus) (vms-9045).
- **Clusterwide logical names** are not sent from OVMX yet. A local change to a clusterwide table is refused with SS$_UNSUPPORTED while other members exist (vms-94a follow-up).
- **Lock-tree remastering on the wire** is not done yet (vms-380), and a former master does not yet answer "not master here" (vms-657).
