## Highlights

- **Remote files over DECnet (vms-6a4).** OVMX's own DCL runs `DIRECTORY node::spec` and `TYPE node::spec` through the remote FAL (#1962). A live round trip against a real VAX runs OVMX's `DIRECTORY`, `TYPE` and `COPY` of `node::spec` against the VAX, and the VAX's `COPY` and `DIRECTORY` against OVMX (#1966). `COPY` is proven only for small files. A restarted OVMX does not reopen a peer's still-held NSP link address (#1958), and its first `SET HOST` to a real VAX after a reboot is accepted (#1964). OVMX runs one NETACP per node, and NETACP no longer keeps its whole idle session pool resident (#1940). A network object's server process reports NETWORK from `F$MODE`, `JPI$_MODE` and `JPI$_JOBTYPE` (#1938). The booted NETACP (`DECNETD.EXE`) finds its LAN unit and waits through VMS services, not the host C library, and its datalink is executive-resident (#1355, #1977). #1977 removed the `getifaddrs` interface lookup and the terminal `poll`. What remains in `DECNETD.EXE` is the FAL and COPY server threads (`pthread_create`) and the FAL-pump `poll`, which sit in argv-flag self-test paths that the booted NETACP does not reach. Removing them is open (vms-0a7, vms-d3cd).
- **Cluster lock manager failover (vms-874f, vms-427, vms-2fa, vms-0db, vms-326).** A survivor re-sends the locks it holds in a departed master's tree as op-0x08 rebuild records. As the new master it installs the records another survivor sends (#1936). A holder told 0xf9 installs its own lock's value block on the resource it now masters, and the deferred grant carries that value block (#1952). Lab captures pin down when a survivor's op-0x08 records follow the barrier (release 5 if its LOCKDIRWT is non-zero, 6 if zero) (#1943), and show a real holder sending its waiting and converting locks (#1956). The executive takes RMS's file-access lock under the name and identity a real VAX uses (#1937). `sys$getlki` `LKI$_RESNAM` returns the resource name's own byte count, NULs included (#1945), and `SYS$GETLKIW` answers `LKI$_PID` from the lock block (#1981). A survivor's queued `$ENQ` rides out a quorum hang when its master departs (#1975), and `ci6_evac.sh` drives and grades the ci.6 evacuation gate (#1974).
- **GCC's cc1 builds on OVMX/Alpha (vms-465, vms-d2a).** `BUILD_CC1.COM` builds GCC's `cc1` on OVMX/Alpha, across 8 CI shards. The RMS, LIBRARY, LINK and DCL fixes the build needed land with it (#1907). The C RTL places P0 mappings lowest-first, so a fragmented P0 still has room for a large request (#1939). `<inttypes.h>` uses `ll` for `PRId64` and its relatives, as the LLP64 alpha-dec-vms C RTL does (#1941). The Alpha executive module `vms.ko` now ships in the co-release bundle and is byte-reproducible under `SOURCE_DATE_EPOCH` (#1960). A compiler's `exit(1)` on OVMX/Alpha is a failure status (#1973). Every release cut ships a bootable OVMX/Alpha set (`vmlinux-boot` and `ovmx-distrib-alpha.img`). The release-acceptance gate boots it from the cut bundle to DCL, and a negative control turns the gate red on a wrong version (vms-f10, #1972). A FAB's `fab$l_xab` is `void *`, as in DEC C, so it chains any XAB type (#1984).
- **DECC$SHR's heap, clock and signals go through VMS services (vms-bc53, vms-593, vms-931).** `malloc` takes its address space from `SYS$EXPREG`/`SYS$DELTVA`, which the executive serves and charges to PGFLQUOTA. The C RTL makes no Linux `brk`, `mmap` or `munmap` call on the heap (#1982). The clock is `SYS$GETUTC`, and the time zone comes from the `SYS$TIMEZONE_*` logicals, so a `DEFINE` of the differential moves the next `localtime()` (#1979). Signals are VMS conditions: `raise()` is `LIB$SIGNAL`, `alarm()` is `$SETIMR` with an AST, `pause()` is `$HIBER`, and `kill()` of a VMS PID is `$FORCEX`, `$DELPRC` or `$SUSPND`/`$RESUME`, authorized by the executive (#2005). The Alpha DECC$SHR links this code, and the x86_64 QEMU tests run the same source.
- **DCL matches VAX V7.3 byte for byte.** These features are byte-checked against VAX V7.3: `ON`, `SET NOON` and `EXIT` (#1942); `GOTO`, `GOSUB`/`RETURN`, block `IF` and `CALL` (#1953); and symbol typing, where a symbol keeps its own type and `$STATUS` is a string (#1951). `SHOW TIME` prints no hundredths and leaves `$STATUS` %X00030001, as VAX V7.3 and Alpha V8.4 do (#1954). `$MOUNT` refuses a second volume with the label of a mounted one (`%MOUNT-F-VOLALRMNT`) (#1893). DCL file verbs take a P1 list of any length, checked against a real VAX V7.3 (#1970). Executive records written after startup reach OPERATOR.LOG on Linux, without a placeholder OPCOM (#1845).

## Known open items

- **`$PROCESS_SCAN` given an unreadable criterion address hangs the caller** instead of returning `SS$_ACCVIO` (vms-705).
- **On OVMX/Alpha the guest's time stamps carry the year 2006** (vms-aedb).
- Remastering is not proven in a cluster evacuation yet (vms-ci.6).
- **Some DCL I/O paths still drop to the host C library:** `@procedure` on a passthrough path, `OPEN` of `SYS$OUTPUT`/`SYS$ERROR`/`SYS$INPUT` and terminal `READ`/`WRITE`, and redirected `SYS$INPUT`/`SYS$OUTPUT` (vms-20c94, vms-28db, vms-5cc). TCP/IP `SHOW INTERFACE` and the TELNET/FTP client's wait do the same (vms-eac6, vms-a6b). The audit for host-C-library calls is ongoing, and more such items are being filed under the `libc-drop` label.
- **DECC$SHR, the VMS C runtime, is still musl underneath, and part of it still reaches Linux.** Process creation (`fork`/`exec`/`wait`) and terminal and pipe I/O still go to Linux (vms-e70f, vms-a66e). Sockets still go to Linux too (vms-99f).
- **Shipped images still parse Unix-style `--flags`:** `DECNETD.EXE` and DCL's `--login`/`--captive`/`--lgicmd` (vms-18c9, vms-838b).
- **DCL passes the DECnet access password to DECNETD over a host pipe** for `COPY`/`DIRECTORY`/`TYPE node::spec` (vms-ad71).
- **Large-file DECnet transfers fail on NSP flow control.** Remote `COPY` is proven only for small files (vms-985).
- **The BG socket veneer waits with `poll()`** (vms-c541).
