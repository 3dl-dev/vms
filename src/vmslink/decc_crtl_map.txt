# decc_crtl_map.txt — OVMX's DEC C RTL (DECC$SHR) universal-name surface map.
#
# The real OpenVMS GCC port (alpha-dec-vms) transparently prefixes every standard
# C name with `decc$` (gcc/config/vms/vms.c; "the standard vms convention for names
# in public shared libraries") — so a port object references `decc$fprintf`, not
# `fprintf`. OVMX's DECC$SHR whole-archives musl libc.a, which DEFINES the bare
# names; mk_decc_shr.sh exports each as a universal aliased to the musl impl via the
# VSI Linker SYMBOL_VECTOR=(universal/internal) form (link.c, vms-3e4 R1a).
#
# THIS FILE is OVMX's own artifact: the set of DEC C RTL entry-point names (a
# PUBLIC, documented ABI — VSI OpenVMS C RTL Reference Manual, Rule-8 sanctioned).
# It is ENUMERATED with the aid of the GPL gcc/config/vms/vms-crtlmap.map (the
# goalpost port's own mapping table — not vendored; only C-standard function names,
# which are facts, are reproduced here). Behavior grounds to lab-Alpha 8.4.
#
# SCOPE (vms-3e4 R1b-1): the NO-DECORATION-FLAG entries only — plain `decc$<name>`
# aliased to the musl `<name>`. Semantics are musl/POSIX for now; the RMS/ACP
# route-through of the file entry points is R2 (vms-dfb, ROUTE-THROUGH) — this map
# provides the linkable CRTL surface, R2 upgrades the file semantics. The
# DECORATED entries (malloc64/float-model/64-bit _X32/_X64 pointer triples/DPML
# MATH$) and the special bootstrap symbols (decc$main, _malloc32/64, vaxc$errno,
# get_vms_errno_addr, C$_EXIT1) are R1b-2 (need the dual-pointer model + real
# VMS-condition-value semantics, oracle-grounded to lab-Alpha).
#
# One standard C name per line. mk_decc_shr.sh nm-filters against the actual
# libc.a, so a name musl does not define is silently skipped (a gap for a later
# rung, surfaced when the port's STRICT link names it — see mk_decc_shr.sh's
# "THE GENERAL RULE").
