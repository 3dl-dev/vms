## Highlights

- **The 3-node cluster demo works: a real VAX and two OVMX nodes form a cluster and every node reaches a DCL prompt.** The pre-tag visitor gate (openvmx-site run GATERUN) ran all 8 visitor orders, with both OVMX nodes built from this release. All 8 reached CN=3, the real VAX V7.3 offered Username:, both OVMX nodes reached a DCL `$`, and there were 0 VAX bugchecks. V0.7-11 and earlier failed this gate: the real VAX bugchecked now and then, and OVMX Node B never offered Username:. Two fixes below close those two failures.
- **A real VAX no longer bugchecks LOCKMGRERR when OVMX joins its cluster (vms-c55).** The executive now holds the cross-node lock requests (ENQ and CONVERT) it would send while a cluster state transition is running, and sends them after the new directory vector is applied. A directory-entry removal raised during a transition is dropped, because the transition discards that entry cluster-wide anyway. A $DEQ still goes out. No new wire shape is sent: the change moves when two existing frame shapes go out (#1734). The crash was intermittent (about 1 fire in 9), so a clean gate run is evidence, not proof. The mechanism is the measured difference between crashing and clean runs (all 3 captured crashes had OVMX lock requests inside a transition, 0 of 11 clean runs did); what the VAX rejects in the crashing frame has not been identified.
- **OVMX Node B now reaches `Username:` as a cluster member (vms-97c2).** DCL staged each `@` command procedure in tmpfs, and under low memory the write failed, so Node B stopped silently in STARTUP.COM. DCL now holds the procedure in memory (#1768). `sys$cancel` also cancels real queued I/O now, where it used to return success and do nothing (#1766).
- **Faster CI.** The bootable image, kernel base, and the layer caches are built once and shared across jobs; heavy legs and the host negative-control sweep run in parallel (#1750 to #1764). This changes how the release is proven, not what the release does.

## Known open items

- **The LOCKMGRERR fix rests on a measured mechanism, not a decoded frame.** What the VAX rejects in cat-0x02 op-0x19 is still unknown (vms-c55 follow-up evidence: tests/lab/captures/vms-c55-transition-hold-20261016).
- **The 0b/05 database request names transfer connection 0**, where real requests name one (19 of 19 in the capture corpus) (vms-9045).
- **Clusterwide logical names** are not sent from OVMX yet. A local change to a clusterwide table is refused with SS$_UNSUPPORTED while other members exist (vms-94a follow-up).
- **Lock-tree remastering on the wire** is not done yet (vms-380), and a former master does not yet answer "not master here" (vms-657).
