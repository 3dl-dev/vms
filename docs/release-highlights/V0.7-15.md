## Highlights

- **Remote files over DECnet (vms-6a4).** OVMX's own DCL runs `DIRECTORY node::spec` and `TYPE node::spec` through the remote FAL (#1962). A live round trip against a real VAX runs OVMX's `DIRECTORY`, `TYPE` and `COPY` of `node::spec` against the VAX, and the VAX's `COPY` and `DIRECTORY` against OVMX (#1966). A restarted OVMX does not reopen a peer's still-held NSP link address (#1958), and its first `SET HOST` to a real VAX after a reboot is accepted (#1964). OVMX runs one NETACP per node, and NETACP no longer keeps its whole idle session pool resident (#1940). A network object's server process reports NETWORK from `F$MODE`, `JPI$_MODE` and `JPI$_JOBTYPE` (#1938). One limit applies: the DECnet datalink is executive-resident (#1355), but NETACP (`DECNETD.EXE`) still uses the host C library for its wait loop (`poll`), its FAL and COPY server threads (pthreads) and NIC detection (`getifaddrs`). That work is open (vms-d3cd), so this path is not yet VMS-native end to end.
- **Cluster lock manager failover (vms-874f, vms-427, vms-2fa, vms-0db, vms-326).** A survivor re-sends the locks it holds in a departed master's tree as op-0x08 rebuild records. As the new master it installs the records another survivor sends (#1936). A holder told 0xf9 installs its own lock's value block on the resource it now masters, and the deferred grant carries that value block (#1952). Lab captures pin down when a survivor's op-0x08 records follow the barrier (release 5 if its LOCKDIRWT is non-zero, 6 if zero) (#1943), and show a real holder sending its waiting and converting locks (#1956). The executive takes RMS's file-access lock under the name and identity a real VAX uses (#1937). `sys$getlki` `LKI$_RESNAM` returns the resource name's own byte count, NULs included (#1945).
- **GCC's cc1 builds on OVMX/Alpha (vms-465).** `BUILD_CC1.COM` builds GCC's `cc1` on OVMX/Alpha, across 8 CI shards. The RMS, LIBRARY, LINK and DCL fixes the build needed land with it (#1907). The C RTL places P0 mappings lowest-first, so a fragmented P0 still has room for a large request (#1939). `<inttypes.h>` uses `ll` for `PRId64` and its relatives, as the LLP64 alpha-dec-vms C RTL does (#1941). The Alpha executive module `vms.ko` now ships in the co-release bundle and is byte-reproducible under `SOURCE_DATE_EPOCH` (#1960).
- **DCL matches VAX V7.3 byte for byte.** These features are byte-checked against VAX V7.3: `ON`, `SET NOON` and `EXIT` (#1942); `GOTO`, `GOSUB`/`RETURN`, block `IF` and `CALL` (#1953); and symbol typing, where a symbol keeps its own type and `$STATUS` is a string (#1951). `SHOW TIME` prints no hundredths and leaves `$STATUS` %X00030001, as VAX V7.3 and Alpha V8.4 do (#1954). `$MOUNT` refuses a second volume with the label of a mounted one (`%MOUNT-F-VOLALRMNT`) (#1893). Executive records written after startup reach OPERATOR.LOG on Linux, without a placeholder OPCOM (#1845).

## Known open items

- **`$PROCESS_SCAN` given an unreadable criterion address hangs the caller** instead of returning `SS$_ACCVIO` (vms-705).
- **On OVMX/Alpha the guest's time stamps carry the year 2006** (vms-aedb).
- Remastering is not proven in a cluster evacuation yet (vms-ci.6).
- **Some DCL I/O paths still drop to the host C library:** `@procedure` on a passthrough path, `OPEN` of `SYS$OUTPUT`/`SYS$ERROR`/`SYS$INPUT` and terminal `READ`/`WRITE`, and redirected `SYS$INPUT`/`SYS$OUTPUT` (vms-20c94, vms-28db, vms-5cc). TCP/IP `SHOW INTERFACE` and the TELNET/FTP client's wait do the same (vms-eac6, vms-a6b).
