## Highlights

- **V0.7-9 could crash a real VAX; V0.7-10 fixes it.** In 3 of the 8 visitor orders of the cluster demo's V0.7-9 gate, a real VAX running OpenVMS V7.3 bugchecked with INVEXCEPTN. After joining, OVMX asked an older member for its clusterwide logical-name database (the 0b/05 request) before that member was ready to answer, while it was still early in its own startup. OVMX now waits for a member to be ready, as a real VAX does. A member is ready when its PARAMS say so, or when it sends its own startup query. That rule comes from 54 real database requests. In a lab run of the same topology that had crashed, OVMX held the request for 63.7 s while the VAX started up, then made it 0.79 s after the VAX's query, with 0 bugchecks (vms-f4e).
- **Cluster transitions:** a member's answer to a logical-name database request is no longer mistaken for a membership-record acknowledgement. While OVMX coordinated a transition, that mistake could count an acknowledgement nobody sent (vms-6e3 follow-up).
- **Lock-tree adoption in the lock manager.** When a lock tree is handed to OVMX, the engine now creates a real master-side lock for each lock a holder reports, under the right parent resource. A cross-node conversion now converts the lock its handle names rather than looking it up by name (vms-14fd). OVMX does not yet take part in a hand-over on the wire. See the known open items.
- **Nothing runs as substrate root after startup.** STARTUP and the startup process give up root once startup is done. Powering off is an executive service that needs CMKRNL. The acceptance battery's root audit counts 0 root processes (vms-137e).
- **Process identity:** `$CREPRC` gives a process its identity when it creates it. SETIDENT is accepted only while a process is being logged in (vms-a2c). On NetBSD the executive no longer creates a process row from an ioctl (vms-6ed).
- **TCP/IP network configuration needs OPER,** as on VMS. A refused `SET ROUTE` or `SET INTERFACE` returns %SYSTEM-E-NOPRIV and changes nothing (vms-ec6).
- **HW_NAME has one source:** `$GETSYI`, `F$GETSYI` and `SHOW CPU` all report the executive's hardware model (vms-21be).

## Known open items

- **The 0b/05 database request names transfer connection 0.** Real requests name a connection (19 of 19 in the capture corpus). This is recorded with its evidence but not fixed in this release (vms-9045).
- **In the cluster demo, a real VAX that boots after the OVMX nodes can stop at `%RMS-E-FNF`** before it offers Username:. This is separate from the bugcheck fixed above.
- **Clusterwide logical names** are not sent from OVMX yet. A local change to a clusterwide table is refused with SS$_UNSUPPORTED while other members exist (vms-94a follow-up).
- **Lock-tree remastering on the wire:** OVMX does not yet parse a real hand-over or send the closing op-0x14 message, because two of its fields are not yet grounded (vms-380). Each adoption that goes unreported is counted.
- **A former master does not yet answer "not master here"** (the 0xf7 reply). Three lab designs have not produced one on real VAXes (vms-657).
