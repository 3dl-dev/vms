# OVMX V0.7-12 Release Notes

Generated by `tools/gen_release_notes.py` from the merged history since `V0.7-11` (29 commits). Do not hand-edit this file -- re-run the tool against the release tag instead.

## Highlights

- **Two ways OVMX crashed a real VAX are fixed.** In the cluster demo, a real VAX running OpenVMS V7.3 bugchecked now and then, with LOCKMGRERR or CNXMGRERR, when OVMX joined its cluster. A master now tells a directory to drop an entry only if that directory holds one; OVMX had been sending a removal to a directory that never registered the entry, which is the cat-0x02 op-0x19 seen in every crash capture (vms-c55, #1776). A connection-manager send that the port did not take now hands its send number back, closing the gap that bugchecked a VAX with CNXMGRERR (vms-fb0, #1775). The executive also holds cross-node lock requests while a cluster state transition is running (#1734). The crashes were intermittent, so a clean run is evidence, not proof: the pre-tag gate runs on this release had 0 VAX bugchecks (about 25 runs across the release candidates), where V0.7-11 bugchecked in 1 of 4 runs of one slow order.
- **The 3-node demo (a real VAX plus two OVMX nodes) reaches a DCL prompt on both OVMX nodes in most join orders.** The pre-tag visitor gate on the tagged commit (openvmx-site run 39111772800) passed 6 of 8 orders; the real VAX admitted both OVMX nodes and offered Username: in every order. The same gate on the previous candidate build passed 8 of 8 (run 39101853519). The two orders that failed hit the known issue below.
- **OVMX Node B no longer stops silently in STARTUP.COM when a low-memory write fails (vms-97c2).** DCL staged each `@` command procedure in tmpfs; it now holds the procedure in memory (#1768), and other runtime paths no longer assume a tmpfs size (#1770). Node B can still run out of memory in other places (vms-4029, below).
- **`$CANCEL` cancels real queued I/O.** It used to return success and do nothing. It now cancels the channel's pending requests, completes the IOSB with SS$_CANCEL, sets the event flag and runs the AST, and a read whose data has already arrived keeps its result (vms-c8c #1766, race fixed in #1772). `$DGBLSC` returns SS$_NOSUCHSEC for a section that is not registered (#1767). `times()` writes the kernel's `struct tms` into its own buffer (#1774).
- **Faster CI.** The bootable image, the kernel base and the layer caches are built once and shared across jobs; the host negative-control sweep runs in parallel. This changes how a release is proven, not what it does.

## Known open items

- **OVMX/VAX Node B can run out of memory during startup (vms-4029).** Node B is a 16 MB VAX. In about 1 in 4 runs of the slower join orders, it logged "No space left on device" for its operator log, then `%OVMX-F-EXECINIT, the startup process did not complete`, and never offered Username:. Its console stays dead, and OVMXA's login can stall with it. No peer crashes. A fix is planned for V0.7-13.
- **The login prompt on a cluster node sometimes does not restart after its 20 s timeout.** `Timeout period expired` is the VMS login-read timeout; in the gate's slowest throttled order, OVMXB sometimes did not print a fresh prompt after it (vms-25f).
- **The 0b/05 database request names transfer connection 0**, where real requests name one (19 of 19 in the capture corpus) (vms-9045).
- **Clusterwide logical names** are not sent from OVMX yet. A local change to a clusterwide table is refused with SS$_UNSUPPORTED while other members exist (vms-94a follow-up).
- **Lock-tree remastering on the wire** is not done yet (vms-380), and a former master does not yet answer "not master here" (vms-657).
