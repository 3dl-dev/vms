## Highlights

- **A real VAX no longer bugchecks LOCKMGRERR or CNXMGRERR when OVMX joins its cluster.** Three changes close the crashes seen in the demo gate. A master now tells a directory to drop an entry only if that directory holds one; OVMX had been sending a removal to a directory that never registered the entry, which is the cat-0x02 op-0x19 seen in every crash capture (vms-c55, #1776). The executive also holds cross-node lock requests while a cluster state transition is running (#1734). A connection-manager send that the port did not take now hands its send number back, closing the gap that bugchecked a VAX with CNXMGRERR (vms-fb0, #1775). The crashes were intermittent, so a clean gate is evidence, not proof.
- **The 3-node cluster demo reaches a DCL prompt on both OVMX nodes in most visitor orders; it does not pass every time yet.** On the tagged commit the visitor gate passed 6 of 8 orders with 0 VAX bugchecks (openvmx-site run 39111772800); both failures are the Node B memory exhaustion below (vms-4029). An earlier build of this release passed 8 of 8 (run 39101853519). V0.7-11 failed this gate.
- **OVMX Node B reaches `Username:` and a DCL prompt as a cluster member when it has memory to (vms-97c2).** DCL staged each `@` command procedure in tmpfs and a low-memory write failed, so Node B stopped silently in STARTUP.COM. DCL now holds the procedure in memory (#1768), and other runtime paths no longer assume a tmpfs size (#1770).
- **`$CANCEL` cancels real queued I/O.** It used to return success and do nothing. It now cancels the channel's pending requests, completes the IOSB with SS$_CANCEL, sets the event flag and runs the AST, and a read whose data has already arrived keeps its result (vms-c8c #1766, race fixed in #1772). `$DGBLSC` returns SS$_NOSUCHSEC for a section that is not registered (#1767). `times()` writes the kernel's `struct tms` into its own buffer (#1774).
- **Faster CI.** The bootable image, the kernel base and the layer caches are built once and shared across jobs; the host negative-control sweep runs in parallel. This changes how a release is proven, not what it does.

## Known open items

- **The demo's Node B (a 16 MB VAX) runs out of memory during startup in roughly 1 in 4 of the slow visitor orders.** It logs "No space left on device", then `%OVMX-F-EXECINIT, the startup process did not complete`, and never offers Username: (vms-4029; runs 39101862126, 39111772800). Free memory falls from 5.8 MB to about 20 KB during boot on every run; the fix is to reduce OVMX's memory footprint. The same exhaustion explains the login prompt that does not return after a timeout (below).
- **The login prompt on a cluster node sometimes does not restart after its 20 s timeout.** `Timeout period expired` is the VMS login-read timeout; in the gate's slowest throttled order, OVMXB sometimes did not print a fresh prompt after it (vms-25f).
- **The 0b/05 database request names transfer connection 0**, where real requests name one (19 of 19 in the capture corpus) (vms-9045).
- **Clusterwide logical names** are not sent from OVMX yet. A local change to a clusterwide table is refused with SS$_UNSUPPORTED while other members exist (vms-94a follow-up).
- **Lock-tree remastering on the wire** is not done yet (vms-380), and a former master does not yet answer "not master here" (vms-657).
