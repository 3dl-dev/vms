## Highlights

- **DECnet SET HOST between OVMX/x86 and OVMX/VAX (vms-9394, vms-5843, vms-acf3).** NETACP on OVMX/VAX opens DECnet through the executive's datalink with the PHY_IO privilege, not as root (#1830). A CI leg runs SET HOST between an OVMX/VAX node and an OVMX/x86 node and proves the datalink from the executive, not from NETACP.LOG (#1856). NETACP works from a volatile node database, so SET HOST reads no file (#1888). Node-database read failures report the real error (#1875). SET HOST to an unknown node says `%SYSTEM-F-NOSUCHNODE` once (#1822). The remote password is not echoed (#1854). A detached process's `/OUTPUT` file is written through RMS (#1857), and a detached process no longer writes on its creator's console (#1816). The demo nodes boot with DECnet configured from the roster (#1819, #1849).
- **ODS-5 volumes (vms-7e7e, vms-b9c, vms-0b0, vms-da9b).** The Files-11 codec reads and writes ODS-5. It is checked against real OpenVMS Alpha V8.4 volumes (#1869). The executive ACP mounts an ODS-5 volume and reads, creates, renames and deletes files with extended names (#1870). The ACP name ABI carries names up to 236 characters (#1872). `vmsfs_master --ods5` masters an ODS-5 volume (#1871, #1885). A directory stays one contiguous extent however large it grows, and the blocks it leaves when it moves are reused (#1897, #1905). The ACP reads a contiguous stretch of a file in one I/O, and extends a file with the blocks that follow it (#1906). RMS parses extended file specs as Alpha V8.4 does (#1878). The parse style is a per-process executive attribute (#1876). DCL has `SET PROCESS/PARSE_STYLE` and the `F$GETJPI` PARSE_STYLE items (#1887). The DEC C RTL translates UNIX and OpenVMS names under `DECC$EFS_CHARSET` and `DECC$EFS_CASE_PRESERVE` (#1882).
- **Native C++ on OVMX/Alpha (vms-5b3, vms-9a0, vms-8ca, vms-ab1a, vms-408).** The native `g++` (cc1plus and libstdc++) compiles, links and runs a C++ program, and `DUMP` of its object matches the cross compiler's (#1859). It also compiles a real GCC source file, `gcc/c/c-lang.cc` (#1865). Native `ar` and a multi-file native build work (#1810). `xgcc` compiles and links a program that includes system headers from the default search path (#1805). libstdc++ and the C++ headers are installed under their real names on an ODS-5 system volume (#1885, #1886).
- **Cluster lock manager toward evacuation (vms-380, vms-ed5, vms-c2b, vms-3ac, vms-85f, vms-9db, vms-b67a, vms-326, vms-194).** OVMX implements the lock-tree remastering messages: the 0e/0f/10/11/12/13 codec, the two answer builders and the op-0x14 (#1825). A real VAX's remaster drives OVMX's adoption engine (#1834). OVMX holds a lock in a tree a VAX masters, and takes the tree when the VAX hands it over. An INVLOCKID bugcheck found in that test is fixed (#1841, #1843). OVMX answers a queued op-0x01. A local release or down-convert tells the peer it granted (#1852, #1863). A sub-lock goes to its parent's master (#1879). DLM resource names are length-counted end to end (#1883). The executive takes the RMS file-access lock, with the byte-exact name and the identity a real VAX uses (#1890). Every cluster member's system disk has its own label, `<SCSNODE>SYS` (#1892).
- **System services and DCL.** New in this release: `$PROCESS_SCAN` (#1828), `F$MODE` and JPI$_MODE (#1831), DCL `ALLOCATE`/`DEALLOCATE` (#1826), `LIB$DO_COMMAND` (#1817), `LIB$GET_LUN`/`LIB$FREE_LUN` (#1848) and `LIB$MOVTUC` (#1814). Also: `SHOW PROCESS` lists the devices a process has allocated (#1838) and prints `Base priority:` from the executive (#1901), `SHOW SYMBOL` shows a global symbol with `==` (#1862), `$GETDVI` returns mounted-volume items (#1809), an image whose `main()` returns runs its exit handlers (#1861), and DEC C `exit()` records the VMS completion status (#1839). The Files-11 ACP enforces the DELETE bit (#1815). OVMX/VAX reads the date from the TOY clock (#1832). LOGINOUT rings one bell for each line typed before `Username:`, as VAX V7.3 does (#1903). The node uses one name everywhere, its SCSNODE (#1829). OPA0: prints only what a VMS console prints, and executive diagnostics go to OPERATOR.LOG (#1833, #1844). DCL returns only real `CLI$_` conditions (#1820, #1842). Constants found nowhere in VMS were removed (#1818, #1827, #1846).

## Known open items

- **`$PROCESS_SCAN` given an unreadable criterion address hangs the caller** instead of returning `SS$_ACCVIO` (vms-705).
- **On OVMX/Alpha the guest's time stamps carry the year 2006** (an object's creation stamp read ` 1-NOV-2006` on 2026-11-01) (vms-aedb).
- Remastering is not proven in a cluster evacuation yet (vms-ci.6).
