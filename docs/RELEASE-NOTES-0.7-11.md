# OVMX V0.7-11 Release Notes

Generated by `tools/gen_release_notes.py` from the merged history since `V0.7-10` (22 commits). Do not hand-edit this file -- re-run the tool against the release tag instead.

## Highlights

- **aarch64 downloads, for the first time.** Every earlier release shipped x86_64, Alpha and VAX assets only. V0.7-11 adds a bootable aarch64 set: an arm64 kernel Image (`vmlinuz`) with the signed in-tree `vms.ko`, the slim initramfs, the pre-installed `ovmx-distrib.img` and the OS kit, attached to the release with an `-AARCH64` suffix (for example `vmlinuz-AARCH64`). It is built on an arm64 runner from the tagged commit by the same `Dockerfile.bootable` pipeline as x86_64. The release-acceptance gate boots those exact files under `qemu-system-aarch64 -machine virt`, runs PARTS and checks the shipped version. If the aarch64 build fails, the whole cut fails (vms-32aa, vms-b58, vms-a07).
- **Clusterwide logical names: a database OVMX cannot decode no longer hangs a member.** When OVMX pulls a member's clusterwide logical-name database and cannot decode all of it, OVMX still answers, so the member's startup goes on. OVMX then marks its own clusterwide tables as not synchronized. It refuses to translate or change names in those tables until a later pull succeeds, so it never answers from a partial copy (vms-94a).
- **Cross-node lock requests name the requesting process** (faithfulness): OVMX's lock requests to another member now carry the requesting process's id instead of zero, as a real VAX's do (#1730). This does not fix the LOCKMGRERR bugcheck; vms-c55 remains a known issue (see below).
- **`DEFINE`, `ASSIGN` and `DEASSIGN` take `/TABLE=name`** and reach the executive's own tables, including `LNM$SYSCLUSTER`. A table this node does not hold is refused with %SYSTEM-F-NOLOGTAB, and nothing is written (vms-aae).

## Known open items

- **The LOCKMGRERR bugcheck (vms-c55) is not fixed.** In the cluster demo, a real VAX running OpenVMS V7.3 still bugchecks with LOCKMGRERR now and then. V0.7-11 includes a change that stops OVMX from removing a directory entry and then asking about that same entry (#1715), but the bugcheck still happens with it. Because the crash is intermittent, a gate run with 0 bugchecks does not show that it is gone.
- **The cluster demo does not pass its visitor gate yet.** The pre-tag gate (openvmx-site run 38824925565) ran 8 visitor orders, with both OVMX nodes built from this release. All 8 reached CN=3 and the real VAX admitted both OVMX nodes, with 0 VAX bugchecks. In all 8, the OVMX/VAX node stopped during startup after the state transition and never offered Username: (vms-97c2).
- **The 0b/05 database request names transfer connection 0**, where real requests name one (19 of 19 in the capture corpus) (vms-9045).
- **Clusterwide logical names** are not sent from OVMX yet. A local change to a clusterwide table is refused with SS$_UNSUPPORTED while other members exist (vms-94a follow-up).
- **Lock-tree remastering on the wire** is not done yet (vms-380), and a former master does not yet answer "not master here" (vms-657).
